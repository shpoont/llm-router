# Working on this project

- Read [README.md](README.md), [PROJECT.md](PROJECT.md) and
  [current work](docs/current-work.md) before acting. Follow relevant links to
  recover context before asking someone to reconstruct it.
- If the project is new, help establish its purpose, intended result and first
  useful piece of work. Ask about missing information when it would materially
  affect the result.
- Work toward the agreed result and respect its scope, constraints and ownership.
  Use the methods and tools appropriate to this project; software and AI are
  relevant only when the work includes them.
- Keep the current agreement, design and active work consistent. When a change
  affects other materials or checks, update the relevant connections too.
- Retain important decisions, reasons, findings and open questions. Distinguish
  agreed direction, proposals, superseded decisions and historical observations.
- Check the result using suitable evidence. Distinguish attempted actions,
  prepared checks, observed outcomes and unresolved uncertainty.
- Use [.project-structure.yaml](.project-structure.yaml) for starter provenance.
  Keep that baseline distinct from the project's own release version.
- Record meaningful changes in [CHANGELOG.md](CHANGELOG.md) and follow
  [versioning and releases](README.md#versions-and-releases). Keep release
  versions, changelog entries and Git tags consistent.
- Before pausing or handing over, leave enough current context for the next
  contributor to continue. Report what was done, checked and left unfinished.

Keep records proportionate. Reuse existing sources and references instead of
creating competing copies. Add project-specific instructions, prerequisites and
commands here as they become relevant.
